# 文件归档器

[English](./README.en-US.md) | 中文

Windows 桌面文件归档工具：把文件拖到窗口分区上，按规则（年/月、ctime/mtime 时间模式、复制/移动）自动归档到目标目录。附带 Everything 搜索联动、分区配色与重命名、窗口状态记忆、高 DPI 适配等。

- 技术栈：Python + tkinter + tkinterdnd2（拖拽），ctypes 直调 Win32 API（标题栏激活态、DragAcceptFiles、文件创建时间读写）
- 打包：PyInstaller 单文件 exe（`文件归档器.spec`，内嵌 icon.ico，UPX 压缩）
- 运行日志：`drop.log`（启动/拖放初始化记录）

## 带时间结构移动

底部开关栏里的「☑ 带时间结构移动」是搬运方式的总开关，默认关闭。

**它解决什么问题**：默认的搬运走 `shutil.move`，同盘没问题，**跨盘时会真复制**，而复制会把文件的「创建时间」重置成当前时刻 —— `shutil.copy2` 也只保得住修改时间，保不住创建时间。于是你搬完一堆老照片，会发现它们的创建日期全变成了今天。

**它怎么做的**：

| 场景 | 做法 | 结果 |
|---|---|---|
| 同一块盘 | `os.rename` 改名 | 瞬间完成，耗时与文件数量无关；所有时间戳原样保留 |
| 跨盘 | 复制 + 把创建时间写回去 | 创建时间、修改时间一个都不变 |
| 拖动文件夹 | 整棵树一起走，不拆开 | 每个文件、每个子目录的创建时间都保留 |

同盘瞬间完成这点值得强调：一个 3000 文件的文件夹也是**几毫秒**搬完，因为它只是改了个目录项的名字，文件一个字节都没动。

**勾选后「修改时间 / 创建时间」两个按钮会收起。** 这两个按钮是「按哪个时间去归类」的选择器；开了「带时间结构移动」就不再按时间去拆结构了，留着只会让人以为还能改。取消勾选则恢复显示。

与「仅复制」的关系：两个都勾上时，复制出来的副本同样保留创建时间（是复制不是搬运，源文件留着）。

**实现要点**：`os.utime` 只能改修改/访问时间，改不了创建时间，必须走 Win32 的 `CreateFileW` + `SetFileTime`；打开目录句柄要带 `FILE_FLAG_BACKUP_SEMANTICS`，否则打不开文件夹。目录的创建时间必须等内容全部落定之后再补写（往目录里写东西会刷新它自己的时间戳），所以用 `os.walk(topdown=False)` 从深到浅处理。

测试见 `test_keep_time.py`（21 项断言，含「copy2 保不住创建时间」的反向对照）。

## 构建

```bash
pyinstaller 文件归档器.spec
```

产物为 `dist/文件归档器.exe`（`build/`、`dist/`、`__pycache__/` 不入库，可再生）。
